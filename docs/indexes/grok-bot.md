# Grok Bot

Product names are tags, not a parallel artifact tree. Grok Bot entries live under their primary types and are grouped here for practitioners who start from the product.

## Channels

In Grok Bot, a **channel** is a group chat of two to six Bots with a shared outcome and visible handoffs. The product's group chat *is* the channel: membership is the roster, the thread is the audit log, and `@` names the owner of the next step.

Use a channel when several Bots need one shared outcome and the handoff itself must be visible. Keep one owner per stage. Mention `@everyone` only for a true group-wide update. Require a human stop before publish, send, purchase, deletion, or any other irreversible action.

The shared cloud computer is not a security boundary. Separate Bots on one account can see the same files, browser sessions, and command-line credentials. Do not treat Bot count as isolation.

## 1:1 handoffs

A Bot can message another Bot asynchronously without opening a group. That is not a channel. Official engineering example: a reproduction Bot files a ticket and hands the fix to a debugging Bot. Send images in a 1:1 message when a teammate must inspect them; current group handoff messages are text-only.

The chief-of-staff pattern may use channels, 1:1 messages, or both. The human still supervises the coordinator, not every specialist lane.
