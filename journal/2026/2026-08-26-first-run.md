## Verified developments

### MCP 2026-07-28 tools contract: untrusted annotations and explicit handles

Accepted as `asf-mcp-artifact-20260826-001`. Hosts must not treat tool annotations as trusted unless the server is trusted, servers must validate tool I/O, a human deny path should exist, and hidden sessions are replaced by caller-bound handles.

Canonical source: https://modelcontextprotocol.io/specification/2026-07-28/server/tools

### MCP 2026-07-28 multi round-trip tool calls

Accepted as `asf-control-loop-20260826-002`. A tool call can pause with `input_required` and optional `requestState`, then resume by retrying the original call with `inputResponses` instead of holding a stream. This is not the Bounded Scout–Evaluate–Publish Loop.

Canonical source: https://modelcontextprotocol.io/specification/2026-07-28/server/tools
Companion: https://blog.modelcontextprotocol.io/posts/2026-07-28/

### MCP 2026-07-28 auth, SSRF, and handle guardrails

Accepted as `asf-guardrail-20260826-003`. Reject token passthrough, require per-client consent before proxying OAuth, constrain metadata URL fetches against SSRF, and never treat a state handle as authentication. Attack walk-throughs from the source were not archived. The exact GitHub path for the HTML page remains unknown.

Canonical source: https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices
